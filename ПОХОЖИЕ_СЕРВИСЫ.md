# Сервисы и системы с похожим функционалом

Подборка для вдохновения и сравнения: учёт аварий/инцидентов, журнал простоев,
дежурная смена, отчётность по сети. Разбито по типам. Коротко — чем полезно нам.

## 1. Ближе всего по задаче (учёт аварий БС, работа дежурного)
- **МТС, Центр оперативного управления** — рассказ о том, как устроена дежурная смена оператора: зонтичный мониторинг, норматив 15 минут на реакцию, одна авария = несколько сообщений по станциям. Прямо наш сценарий. https://habr.com/ru/companies/ru_mts/articles/308044
- **Vodafone Cell Site Management** (в реестре российского ПО) — автоматизация управления базовыми станциями для инженеров эксплуатации и мониторинга. https://soware.ru/products/vodafone-cell-site-management
- **MYCOM OSI — Early Warning System** — слежение за трафиком каждой БС против суточного прогноза, подсветка «просевших» станций. Идея для вкладки статистики. https://www.apmdigest.com/mycom-osi-launches-early-warning-system-for-nocs-and-socs
- **Cellnex — Incident Management** — как телеком-инфраструктурная компания показывает процесс обработки инцидентов. https://cellnex.com/gb-en/incident-management

## 2. Open-source — можно развернуть и посмотреть вживую
Полезно: у них зрелые таблицы, формы инцидентов, фильтры, экспорт, роли — есть что подсмотреть по UX.
- **GLPI** — ITSM + инвентаризация, заявки и инциденты. Самый близкий по «таблица + форма + роли + экспорт». https://glpi-project.org
- **iTop** — CMDB + управление инцидентами, community-версия. https://www.combodo.com/itop-193
- **Zammad** — современный help desk: SLA, workflow, самообслуживание. https://zammad.org
- **osTicket** — лёгкая тикет-система: очереди, шаблоны, базовые отчёты. https://osticket.com
- **Zabbix** — мониторинг с «проблемами»/авариями, severity, подтверждением. Эталон NOC-интерфейса, российские корни. https://www.zabbix.com/screenshots
- **Grafana** — дашборды и панель Alerting; пример статистики простоя и графиков. https://grafana.com/grafana/dashboards

## 3. Коммерческие инциденты / дежурства (референс UX)
- **PagerDuty** — карточка инцидента, таймлайн, эскалации, дежурства. https://www.pagerduty.com
- **Opsgenie (Atlassian)** — алерты, расписания дежурств, пост-мортемы. https://www.atlassian.com/software/opsgenie
- **AlertOps — Telecom** — маршрутизация сетевых инцидентов по сегменту/региону/времени, журнал с привязкой к SLA. https://alertops.com/solutions/telecommunications/
- **Atlassian Statuspage** — как показывать аварии, их длительность и затронутые сервисы. https://www.atlassian.com/software/statuspage
- **Better Stack / Uptime** — журнал простоев и отчёты по аптайму. https://betterstack.com/uptime

## 4. Методички по отчётности NOC (что считать и как показывать)
- **INOC — The Complete Guide to NOC Reporting** — какие отчёты нужны NOC, в т.ч. «причины простоя» (RFO) для хронических проблем. https://www.inoc.com/blog/network-operations-center-reporting
- **INOC — NOC Incident Management Guide** — процесс обработки инцидента от регистрации до закрытия. https://www.inoc.com/blog/noc-incident-management-guide
- **Towards Data Science — Incident-First Blueprint for Telecom AIOps** — как от потока алармов переходить к инцидентам (борьба с дублями). https://towardsdatascience.com/stop-managing-alarms-an-incident-first-blueprint-for-telecom-aiops/

## Что из этого стоит перенять для нашего проекта
- **Статусы/severity цветом** (как в Zabbix) — у нас есть категории 1/2/3, можно усилить подсветку.
- **Дедупликация**: одна авария электросети = много БС. В ТЗ это уже заложено полем «Количество БС» и сектором «С» — стоит обсудить с экспертом (см. вопросы 9, 27 в файле вопросов).
- **Отчёты по причинам простоя (RFO)** и сводка по ТЦ/направлению — кандидаты во вкладку «статистика» (п. 2.2 ТЗ).
- **Таймлайн инцидента** (PagerDuty) — на будущее, если понадобится история изменений записи.
